CMBpipeline-pixell · Tasks 1–2

How the code fits together

A map of the repository: what each script does, which ones call which, and how to build the DeepWiener training set on a laptop or on the IAS cluster.

The idea in one paragraph

CMBpipeline projects spherical Q/U maps onto a flat tangent plane, interpolates them onto a grid and uses flat-sky FFTs. This repository keeps the maps on the sphere: Q/U are synthesised directly with pixell.curvedsky on a CAR cut-out (9.6′, 1120 × 320 pixels) of an exact full-sky grid, so curved-sky transforms stay exact. Task 1 measured what the projection costs; Task 2 produces the training tensors for DeepWiener_threechannels on these CAR maps, with exactly CMBpipeline's channel layout.

The scripts, one by one

config.dict
parameters

A Python dict literal in CMBpipeline's format. Same values as CMBpipeline (SO "rect" mask, r = 0.034, 23′ beam, noise 5×10⁻⁷ μK² sr, 1000 / 100 / 30 maps) plus the CAR keys: res_arcmin = 9.6, npixels_x × npixels_y = 1120 × 320, lmax_sim = 1535 and explicit seeds cmb_seed0 = 0, noise_seed0 = 100000.

Paths point to the cluster: code in /home/bcostanza/wf-curve-pixell/, tensors in /data/bcostanza/curve-pixell/, CMBpipeline code read from /home/bcostanza/wf-curve/pol/. Every difference with CMBpipeline's config is listed in docs/03_task2_dataset_plan.md.

Task 2
config_loader.py
load_config(), bin_edges()

Finds the config (explicit path → $WF_CONFIG → ./config.dict → next to the module), checks required keys, checks that both image sides are multiples of 32, and derives absolute file names: name_train, name_valid, mask_car_path, variance_car_path, spectra_path, seeds_path… It also appends the CMBpipeline source folder to sys.path, after this repository's own modules so these keep precedence.

Point it at another config with WF_CONFIG=/path/config.dict. The local test uses results/task2/config_local.dict (3 + 2 maps, local paths).

Task 2
make_dataset.py
class make_dataset

The core of Task 2. Same class name and method layout as CMBpipeline's make_dataset. For each map:

  • Geometry — get_sky_region reads the SO mask and hits with CMBpipeline's make_SO_mask; car_geometry cuts 1120 × 320 pixels around the mask out of the 9.6′ fejer1 full-sky grid; healpix_to_car copies mask and hits to CAR (value of the HEALPix pixel containing each CAR pixel centre).
  • Signal — get_alm: curvedsky.rand_alm from the CMBpipeline spectrum, beam applied to aE, aB; get_QUmaps_car: curvedsky.alm2map(spin=2) straight onto the cut-out.
  • Noise — get_inhomogenous_noise: σ² = N(n̂)/Ωpixel, with N(n̂) CMBpipeline's hits-based noise per steradian. Because CAR pixels shrink as cos(Dec) (27 → 84 arcmin² over the footprint), σ² rises toward the southern edge while the noise power spectrum stays flat at N. get_inho_noise draws one realization.
  • Assembly — make_inho_maps_car returns mask × (signal + noise); make_train_dataset loops over maps and writes the tensors and auxiliary files.
Task 2
run_dataset.py
entry point

Same role as CMBpipeline's run_dataset.py: load_config() → make_dataset(...) → make_train_dataset(...), then prints the elapsed time. It holds no logic of its own; everything comes from the config.

Task 2
slurm/data.sh
cluster job

Activates torch_cmb, moves to src/, logs the git commit and runs run_dataset.py. 4 CPUs, 32 GB, 4 h; the log goes to /home/bcostanza/wf-curve-pixell/logs/data_<jobid>.out.

Task 2
sky_input.py

Task 1's common input: one set of seeded, beamed aℓm from CMBpipeline's fiducial spectrum, optionally E-only or a narrow ℓ-shell (for mode-mixing tests). Importing it also puts ../CMBpipeline/source on the path.

What one training sample looks like

ChannelContentUnitsNotes
0Qobs = mask · (Q + nQ)μK0 outside the mask
1Uobs = mask · (U + nU)μK0 outside the mask
2binary mask–same in every sample
3pixel noise variance σ²μK²analytic; same in every sample

Tensors are float32 of shape (N, 4, 320, 1120): 5.7 GB for the 1000 training maps, 0.57 GB for the 100 validation maps. No normalization is stored: the training loader subtracts each map's mean and applies map_rescale_factor, as in CMBpipeline. Map i uses CMB seed cmb_seed0 + i and noise seed noise_seed0 + i; validation maps continue after the training ones, so no seed repeats.

Next to the tensors, aux/ holds the CAR mask, hits and σ² maps as FITS (with their WCS, so later steps can return to the sphere), the cached spectra and the seed list.

How to run it

  1. Small local test

    Uses results/task2/config_local.dict (3 train + 2 valid maps, local paths). Requires ../CMBpipeline/source next to the repository.

    cd src
WF_CONFIG=../results/task2/config_local.dict python run_dataset.py

    Then open notebooks/02_dataset_check.ipynb to check the result.

  2. Full dataset on the IAS cluster

    Log in through the gateway to the submit node, then submit from the repository root:

    ssh bcostanza@ssh.sns.ias.edu
ssh apollo-login1.sns.ias.edu
cd /home/bcostanza/wf-curve-pixell
git pull                      # get the latest code
mkdir -p logs
sbatch slurm/data.sh
squeue -u bcostanza           # follow the job
tail logs/data_<jobid>.out

    Outputs: /data/bcostanza/curve-pixell/train_nCMB_r034_beam_car9.6_cut1120x320_maskSO_inho_hitsSO.pt and valid_…pt; auxiliary files in /home/bcostanza/wf-curve-pixell/aux/.

  3. Changing parameters

    Edit src/config.dict, or copy it and point WF_CONFIG at the copy. Change dataset_tag whenever you change the physics, so new files never overwrite old ones.

Environment: the cluster's torch_cmb env needed pixell; pixell 0.32.7 (same as local) was added with pip on 2026-10-07. Nothing else was upgraded. The cluster has ducc0 0.41 vs 0.38 locally.

Status and open points

  • Done: the full dataset was generated on 2026-10-07 (job 17385111, commit 119a121, 9 min 50 s, 7 GB peak memory). Training maps 0–2 are identical to the local test maps, which used the same seeds.
  • Training itself is not part of Task 2. CMBpipeline's loss (losses.py) and OQE (PowerSpectrum.py) use flat-sky FFTs with dx, dy and ℓ = |k|; on CAR maps they need curved-sky counterparts.
  • map_rescale_factor (0.8382) comes from CMBpipeline and may need retuning for CAR pixel statistics.
  • The σ² channel varies with Dec because of the CAR pixel area. This is the correct per-pixel variance and gives the right noise spectrum, but the network has to learn the cos(Dec) pattern; band-limited noise is an alternative if that turns out to hurt training.
